/ 04 · HERMES AGENT SPEC

Hermes Agent — 任務編排實作規格

Hermes 是 OpenClaw 管線中 Qwen3 與 Home Assistant 之間的那一層：把模型輸出的自然語意轉成「可驗證、可重試、可回滾」的工具呼叫序列。本頁為可直接實作的規格 — 工具清單與 function schema、編排與失敗處理、介面契約與權限模型、記憶與上下文、M4 併發策略，以及股票分析模組與 v0.4 的節能管家模組（憲章 VI：所有空調／燈光／家電計畫執行前經 energy.clamp 守門，只收緊不放寬）。

工具清單與 Function Schema

Tool Registry

Hermes 啟動時從 tools/*.yaml 載入註冊表，並把精簡後的 schema（名稱＋參數＋一行描述，約 1.1k tokens）注入 Qwen3 的 system prompt。模型只能呼叫註冊表內的工具；未知工具名一律拒絕並回覆「這個我還不會」。點選任一工具看完整 JSON Schema。

多步驟編排：條件、重試、回滾
Orchestration

  
每一次語音指令產生一個 Plan（有向步驟串），Hermes 逐步執行並把每步結果寫進 transaction log。任何一步失敗且不可重試時，依 log 反向執行補償動作（compensating action），確保不會留下「燈開了但冷氣沒開」的半套狀態。

  

    
01 PARSE
解析計畫
LLM JSON → Plan 物件
schema 驗證失敗即重問

    
02 GUARD
前置條件
device_online · 時段
睡眠模式 · 權限 scope

    
03 CONFIRM
人工確認
語音覆誦 → 「好」
逾時 12s 取消

    
04 DISPATCH
分派執行
HA / MQTT / Matter
逐步寫入 tx log

    
05 RETRY
重試
指數退避 3 次
0.4s / 1.2s / 3.6s

    
06 SETTLE
收斂或回滾
全成功 → TTS 回報
失敗 → 反向補償

  

  

    

      
Plan 定義（YAML）

      
「Allen 回家了」→ 3 個動作步驟，各自帶 guard、retry 與 compensate。


# hermes/plan.yaml — 由 LLM 輸出後經 schema 驗證
plan_id: pln_2f7a
intent: home_arrival
confirm: voice          # 全部動作皆需確認
timeout_ms: 8000
steps:
  - id: s1
    tool: light.activate_scene
    args: { area: living, scene: "Welcome" }
    guard: [ device_online, not_sleep_mode ]
    retry: { max: 3, backoff: exponential }
    compensate: light.restore_snapshot

  - id: s2
    tool: climate.set
    args: { entity: living, temp: 24, mode: cool }
    guard: [ device_online, temp_in_range(18,30) ]
    depends_on: [ s1 ]
    retry: { max: 2, backoff: exponential }
    compensate: climate.restore_snapshot

  - id: s3
    tool: cover.set_position
    args: { entity: living_curtain, position: 100 }
    guard: [ device_online, sun_above_horizon ]
    on_fail: skip        # 非關鍵，失敗不中止

on_success: tts.say("歡迎回家，冷氣設為 24 度")
on_abort:   tts.say("客廳冷氣沒回應，已還原燈光")

    

    

      
執行紀錄與回滾（實際跑一次）

      
s2 連線逾時 → 重試 2 次仍失敗 → 反向補償 s1 → 回報人話原因。

介面契約與權限模型
Interface Contract & Permissions

  
Hermes 不直接碰設備。三條下行通道各有明確契約、逾時與重試語意；上行狀態統一經 HA state machine 正規化後進 Hermes 的 world model，避免 Zigbee／Matter／WiFi 三套語彙混用。

  

    

      
通道契約逾時 / 重試冪等覆蓋設備

      
        
HA REST
主要路徑		POST /api/services/{domain}/{svc}
Bearer LLAT · JSON body		1.1s / 3 次
指數退避		是（key 帶入 context）Hue 22 · 空調 5 · 窗簾 2 · Roborock

        
HA WebSocket
狀態訂閱		ws://ha:8123/api/websocket
subscribe_events: state_changed		心跳 20s
斷線自動重連		—（唯讀）全部 entity 狀態進 world model

        
MQTT
感測與告警		hermes/cmd/#（下行）
hermes/evt/#（上行）· QoS 1		QoS1 保證送達
retained 僅狀態主題		是（msg_id 去重）Aqara 溫濕度 · 門窗 · 自訂告警

        
Matter / Thread
未來設備		經 HA Matter server
不直連 fabric		依 HA 預設
2 次		由 HA 保證預留（新購 Matter 燈具／插座）

      
    

  

  

    

      
權限 Scope 矩陣

      
每個工具標註 scope；Hermes 在 dispatch 前比對 caller 身分（語音者辨識或 App session）與時段策略。

      

        
Scope允許確認限制

        
          
read狀態查詢、感測讀值、股價不需無

          
write.comfort燈光、空調、窗簾、音量需口頭確認23:00–07:00 主臥音量鎖 20%

          
write.appliance掃地機、除濕、插座需口頭確認睡眠模式下拒絕

          
write.securitySOS 簡訊、警示燈效需確認（SOS 例外：長按硬體鍵直通）僅 Allen / Ann 聲紋

          
finance.sim模擬單、持股記帳需確認＋覆誦標的與股數不連券商、不下真實單

          
net.egress外部 API（股價、天氣、行事曆）不需（唯讀）白名單網域 · 5s 逾時 · 失敗降級

        
      

    

    

      
確認策略（自主程度：全部要確認）

      
任何會改變家中實體狀態的動作，Hermes 都先覆誦再執行。只有唯讀查詢與既有 HA 自動化（30+ 場景）可無聲執行。


# hermes/policy.yaml
autonomy: confirm_all
confirm:
  channel: [ voice, ha_companion_push ]
  phrase: "要我{動作摘要}嗎？"
  accept: [ "好", "可以", "執行", "yes" ]
  reject: [ "不用", "取消", "算了" ]
  timeout_s: 12        # 逾時視為取消
  quiet_hours:          # 23:00-07:00 改推播確認
    window: [ "23:00", "07:00" ]
    channel: [ ha_companion_push ]

exempt:                 # 免確認白名單
  - scope: read
  - tool: emergency.sos   # 硬體長按，不可再攔
  - source: ha_automation # 既有 30+ 場景照舊

never:                  # 永不允許
  - broker.place_order    # 真實下單：介面預留但停用
  - lock.unlock_remote

    

  







  
記憶與上下文
Memory & Context

  
三層記憶，全部存在 Mac mini M4 本地的 SQLite（hermes.db），不出家門。每次推理只把「摘要後」的上下文塞進 prompt，控制在 600 tokens 內以維持 N100 的延遲預算。

  

    
短期 · 對話窗
session · TTL 10 min

      
  • 最近 6 輪對話與指代（「再暗一點」「那間房」）
  • 上一個 plan 與其結果，供「還原剛剛那個」
  • 待確認的 pending plan

    
工作 · 世界模型
world model · live

      
  • 誰在家：person.allen / person.ann + 手機藍牙
  • Ann 班別（input_select.ann_shift）與睡眠模式
  • 全設備線上狀態、室溫濕度、窗簾位置

    
長期 · 偏好學習
preferences · 累積

      
  • 常用溫度：Allen 24°C / Ann 26°C（近 30 天眾數）
  • 常用亮度與色溫、慣用叫法別名
  • 自選股清單與成本、被駁回的建議類型

  

  

    

      
資料表結構

      
SQLite · WAL 模式 · 每晚 03:00 隨 HA 備份一起打包。


-- hermes.db
CREATE TABLE session (
  id TEXT PK, started_at INT, speaker TEXT,
  turns JSON,            -- 最近 6 輪
  last_plan_id TEXT, expires_at INT );

CREATE TABLE world (
  entity TEXT PK, domain TEXT, state TEXT,
  attrs JSON, updated_at INT, online INT );

CREATE TABLE pref (
  key TEXT PK,           -- allen.climate.temp
  value JSON, n INT,     -- 樣本數
  confidence REAL,       -- 0-1，<0.6 不主動套用
  updated_at INT );

CREATE TABLE alias (
  phrase TEXT PK,        -- "小房間"
  entity TEXT,           -- light.second_bedroom
  learned_from TEXT );

CREATE TABLE holding (
  symbol TEXT PK, shares INT, cost REAL,
  note TEXT, updated_at INT );

股票分析模組
Market Analyst · analysis + paper trading only

  
新增能力：Hermes 可在盤後掃描自選股、盤中條件告警、即時語音問答、收盤產出圖卡，並追蹤持股損益。只分析與模擬單，不連券商、不下真實單 — broker 介面在 registry 中保留但預設停用（never 清單）。

  

    
13:30 收盤後

14:00

06:35 隔日

09:00–13:30

選股規則與告警條件

      
規則寫在 hermes/market.yaml，語音可調參數但需確認。資料源為公開行情 API，快取 15 分鐘，失敗時明說「拿不到報價」而非猜測。


# hermes/market.yaml
universe: watchlist        # 自選股，不掃全市場
source: { api: twse_public, cache_min: 15, timeout_s: 5 }

screen:                    # 盤後掃描，加權評分
  - rule: price > ma20 > ma60        weight: 30
  - rule: volume > ma_volume20 * 1.5 weight: 25
  - rule: 40 < rsi14 < 70            weight: 20
  - rule: macd_hist crossed_above 0  weight: 25
  top_n: 3
  min_score: 60           # 不足就說「今天沒有符合的」

alerts:                    # 盤中，每檔每日最多 2 次
  - name: breakout
    when: price > high_20d
    notify: { light: pulse_blue x3, push: true }
  - name: volume_spike
    when: volume_5m > avg_5m * 3
    notify: { push: true }
  - name: stop_loss
    when: price < holding.cost * 0.92
    notify: { light: pulse_red x3, push: true, tts: true }

paper_trade:
  enabled: true
  confirm: repeat_back      # 覆誦標的＋股數＋價格
  ledger: hermes.db/paper_orders
broker: { enabled: false, note: "介面預留，policy.never 封鎖" }

disclaimer: "以上為資料整理，非投資建議。"   # 每次播報結尾

    

    

      
語音問答與模擬單

      
兩段實際對話：唯讀查詢直接回，模擬單則覆誦後才記帳。


# A. 唯讀查詢 — 免確認
user: "2330 現在怎樣？"
hermes:
  tool: market.quote { symbol: "2330" }
  tool: market.indicators { symbol: "2330", set: [ma20,ma60,rsi14,vol] }
  latency: 1.9s  (API 1.4s + LLM 0.5s)
tts: "台積電 1085 元，漲 1.2%。站上 20 日均，
      量能是均量的 1.4 倍，RSI 58。非投資建議。"

# B. 模擬單 — 覆誦確認
user: "幫我模擬買 2330 一張"
hermes:
  guard: scope=finance.sim ok · broker=disabled ok
  confirm: "模擬買進台積電 1000 股，
            以現價 1085 記錄，確認嗎？"
user: "好"
  tool: market.paper_order
    { symbol: 2330, side: buy, shares: 1000, price: 1085 }
  → paper_orders #17 recorded
tts: "已記錄模擬買進。目前模擬組合 4 檔，帳面 +3.2%。"

# C. 失敗降級
api: twse_public TIMEOUT 5s → retry 1 → fail
tts: "現在拿不到報價，網路或交易所那邊有狀況，
      要我五分鐘後再試一次嗎？"       # 不編造數字

    

  

  

    ⚠️
    
邊界：Hermes 的股票能力是「資料整理與提醒」，不是投資建議，也不具備下單能力。broker.place_order 永遠在 policy.never 清單內；若未來要開啟，需同時改 policy、換用有 scope 限制的券商憑證，並保留第二道人工確認。每次播報與圖卡都附免責聲明。

  







  
Mac mini M4 上的併發與佇列策略
Concurrency & Resource Budget

  
Mac mini M4（10 核 CPU／10 核 GPU／16 GB 統一記憶體）上，Ollama（Qwen3 8B）與 wyoming-mlx-whisper（large-v3-turbo）原生跑在 macOS 並用 Metal GPU 加速；Home Assistant 以 HAOS 虛擬機（UTM 橋接，192.168.0.88）運行，Zigbee 走網路型 SLZB-06 協調器（192.168.0.25）。LLM 改由 GPU 推理後不再吃滿 CPU，Hermes 仍保留「LLM 車道 + 快速通道」設計 — 查狀態、抓報價、告警走 fast lane，永遠不排在 LLM 後面。
