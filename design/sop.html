A設計審查

現有設計文件（總覽 / 拓樸 / 30 場景 / OpenClaw）完整度高、視覺清晰，且「本地優先、低延遲、無雲端依賴」的核心理念與你的安全考量一致。以下是把架構從 HA Black（N100）+ 自建 OpenClaw 轉為 Mac mini M4 + Home Assistant + Hermes Agent + Apple Home 時，必須修正或注意的七個重點。

重要度項目發現與修正建議
關鍵 主機平台變更
N100 → Mac mini M4		 設計以 HAOS 直接安裝於 HA Black（x86 N100）為前提。macOS 無法原生安裝 HAOS。Mac mini M4 上的正確做法是：
① （建議）以虛擬機執行 HAOS（UTM／Apple Virtualization，aarch64 映像）→ 保留 Supervisor 與完整 Add-on 生態；
② HA Container（Docker）→ 輕量但無 Supervisor／Add-on，需自行以容器補齊 Mosquitto、Zigbee2MQTT、Whisper、Piper。
本 SOP 採方案①為主線。
關鍵 HomePod 不能當語音衛星 OpenClaw 設計讓 HomePod 透過「AirPlay → mic-bridge」把麥克風音訊送進 STT。HomePod 是封閉裝置，不會把麥克風開放給第三方，此路徑技術上不成立。修正：HomePod／HomePod mini 定位為 Apple Home（Siri）語音入口 + 播報輸出；本地 LLM 語音迴圈另用 Home Assistant Voice PE（或 ESP32-S3 Atom Echo／手機 Assist）作為喚醒詞麥克風衛星。
關鍵 Panasonic 空調「100% 本地」 設計宣稱 panasonic_cc 為「100% 本地端控制」。實際上 CS-UX 系列內建 IoT 走的是 Panasonic Comfort Cloud（雲端），該整合仍需連網登入雲端。若要真正本地 + 進 Apple Home，建議加 紅外線閘道（SwitchBot Hub 2／Broadlink RM4）由 HA 以 IR 本地控制；或接受空調這一項為雲端依賴，並在文件中據實標示。
重要 Zigbee 無線電 Mac mini 無內建 Zigbee。Aqara C3 窗簾與（若採原生 Zigbee 的）感測器需 USB Zigbee 協調器（Home Assistant Connect ZBT-1／Sonoff ZBDongle-E）透傳進 VM，跑 Zigbee2MQTT。替代方案：Aqara Hub M3（支援 Matter）→ 同時橋接進 Apple Home 與 HA。Philips Hue 維持自有 Hue Bridge（最佳實務，勿拆進 Z2M）。
重要 Apple Home 整合方式 要讓 HomePod／iPhone 的「家庭」App 與 Siri 能控制全屋，需在 HA 啟用 HomeKit Bridge 整合，把精選 HA 實體匯出成 HomeKit 配件。原設計未涵蓋此層。定位：Apple Home = 人／Siri 的操作面；HA = 自動化大腦。
重要 遠端存取的攻擊面 設計以「固定 IP + DuckDNS + 對外開 443/8123 反向代理」提供遠端存取。既然核心訴求是安全，直接把 HA 暴露在公網並不理想。建議改用 Tailscale／WireGuard VPN 或 Nabu Casa Cloud，不對外開任何 port；DuckDNS 方案列為備援並加嚴（詳見 Phase 3 / D 安全強化）。
留意 BOM 重複與其他細節 設備清單第 14 項仍列「智能中樞 Home Assistant Black」，與新主機 Mac mini M4 功能重複——建議 Mac mini 為主機，HA Black 退居備援或省略。其他：Dyson HP10 屬非連網機型（需 IR/智慧插座才可自動化）、虎牌電鍋與櫻花淨水器無官方智慧整合（僅能以 Tapo 插座做用電偵測）、Sony Bravia 建議用本地 braviatv 整合並開 AirPlay/HomeKit。
✓
沿用的優點：30 個自動化場景的分類、觸發邏輯與 YAML 樣本、五層網路拓樸的分層概念、以及「本地 AI 語音管家」的四段式管線（STT→LLM→編排→TTS）都可直接沿用。本 SOP 只是把「跑在哪、麥克風從哪來、雲端邊界在哪」修正到真實可行的組態。

B目標架構

修正後的分層架構。核心原則：本地優先、雲端最小化、公網零曝露、Apple Home 為前台、HA 為大腦。

                 └─ 遠端存取：Tailscale / WireGuard VPN（建議）

                 │             ├─ Add-on: Zigbee2MQTT  ◄── USB Zigbee 協調器
                 │             ├─ Add-on: faster-whisper (STT, Wyoming)

ℹ︎
「Hermes Agent」在本架構的定位：由 Ollama 於 macOS 原生執行 hermes3（NousResearch Hermes 3，具函式呼叫/工具調用能力，Apple Silicon Metal 加速），透過 HA 內建的 Ollama 對話整合 + Assist LLM API 直接呼叫 HA 服務——即設計中「Tool Calling · Function Routing」的角色。相較原 N100 CPU-only 的 Llama 3，M4 的 Metal 推理更快、可跑更大模型。

D建置 SOP（Phase 0–7）

依序執行；每階段都有「目標／步驟／驗收」。指令以 Apple Silicon macOS 為準。建議每完成一階段就做一次 HA 快照備份。

P0

前置準備與安全基線

½ 天
目標：把網路、帳號、命名規則與備援策略先立好，避免後面返工。

步驟

  1. 盤點固網：確認中華電信數據機模式。若為「浮動 IP + 你自己想用 VPN」即可，不一定需要固定 IP；用 VPN 遠端存取時可省下對外曝露。
  2. 路由器 BE3600：韌體更新 → 建立 兩個 SSID/VLAN：Home（人）與 Home-IoT（設備）。IoT 網段關閉「跨網段存取」，僅放行 HA 主機能連到 IoT。
  3. 規劃命名規則：實體 ID 以 區域_設備_功能（如 living_ac、bedroom_curtain），區域用 HA Areas：玄關/客餐廳/主臥/次臥/陽台/廚房/浴室。
  4. 準備帳號：HA 建 Allen / Ann 兩個使用者；Apple 家庭邀請雙方 Apple ID。
  5. 備援策略先定：HA 每日快照 + 每週外部備份（見 Phase 7 / E）。準備一顆外接 SSD 或 NAS 目的地。

驗收

  • 兩個 VLAN 可各自上網、IoT 段無法主動連主網段
  • 路由器韌體為最新、已改預設管理密碼、關閉 WAN 側管理
  • 命名規則與區域清單文件化
P1

Mac mini M4 系統設定與強化

1–2 hr
目標：把 Mac mini 設定成穩定、安全、可 24/7 無人值守的伺服器。

步驟

  1. 系統更新至最新 macOS；設定固定內網 IP（於路由器做 DHCP 保留，如 192.168.10.2）。
  2. 安全強化：開啟 FileVault 全碟加密、開啟 系統防火牆（隱身模式）、關閉不必要的分享。
  3. 電源：系統設定 → 節能 →「防止自動進入睡眠」「電力中斷後自動開機」「當機自動重啟」全開；關閉螢幕睡眠對背景服務無影響。
  4. 無人值守登入：啟用自動登入或設定服務於開機執行（VM 與 Ollama 均設為登入時啟動）。
  5. 安裝套件管理：
    # Homebrew（Apple Silicon）
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
  6. 開啟遠端管理：僅在內網啟用「螢幕共享」與（選用）SSH；不對公網開放。
⚠︎
Mac mini 是整套系統的單點。務必接 UPS，並在 Phase 7 建立「異地備份」，以便硬體故障時能在新機快速還原 HA。

驗收

  • 斷電再上電後 Mac mini 會自動開機並回到可服務狀態
  • FileVault 已加密、防火牆開啟
  • 可從內網另一台裝置以螢幕共享連入
P2

安裝 Home Assistant（HAOS on VM）

1–2 hr
目標：在 Mac mini 上以虛擬機執行最新穩定版 HAOS，取得完整 Supervisor / Add-on 能力。

步驟（主線：UTM + HAOS aarch64）

  1. 安裝 UTM：brew install --cask utm（或 App Store）。UTM 使用 Apple Virtualization framework，M4 效能佳。
  2. 下載 HAOS aarch64（generic-aarch64） 最新穩定版 .qcow2／VMDK 映像（Home Assistant 官網 OS 下載頁）。
  3. 在 UTM 新增虛擬機：
    # 建議配置
CPU  : 2–4 vCPU
RAM  : 4 GB（若 VM 內也跑 Whisper 可給 6 GB）
Disk : 64 GB
Net  : Bridged（橋接到實體網卡，讓 HA 取得 IoT/主網段可達的 IP）
  4. 掛載 HAOS 映像開機；等待 HAOS 初始化，於瀏覽器開 http://homeassistant.local:8123 或 http://<VM-IP>:8123。
  5. 完成 Onboarding：建立擁有者帳號、設定居住地/時區/單位、命名為「Allen & Ann Home」。
  6. 設定 VM 開機自啟：UTM 偏好設定 → 「Start automatically」；或用 utmctl 於 launchd 開機啟動。
  7. 安裝核心 Add-on：File editor / Studio Code Server、Mosquitto broker、Zigbee2MQTT、faster-whisper、Piper、Samba/備份工具。
ℹ︎
方案 B（HA Container / Docker）：若不想跑 VM，可用 OrbStack/Docker Desktop 跑 ghcr.io/home-assistant/home-assistant:stable，另以獨立容器補 Mosquitto、Zigbee2MQTT、Wyoming-whisper、Wyoming-piper。缺點：無 Supervisor/一鍵 Add-on/內建備份，維運較繁瑣。本 SOP 後續以方案 A 為準。

驗收

  • 重開 Mac mini 後 VM 自動啟動、HA 於 8123 可登入
  • Supervisor → Add-on 商店可正常瀏覽/安裝
  • 已建立第一個手動快照備份
P3

網路、遠端存取與 TLS

1 hr
目標：安全地遠端存取 HA，優先「公網零曝露」。

步驟（建議：VPN 優先）

  1. 方案 1（強烈建議）Tailscale：安裝 HA Tailscale Add-on 並登入，手機同裝 Tailscale。出門即透過私有網狀網路連 http://<ha-tailscale-ip>:8123，路由器不需開任何 port。
  2. 方案 2 Nabu Casa Home Assistant Cloud：訂閱制、一鍵遠端 + 免自架 TLS，同時支援 Google/Alexa（此案以 Apple 為主，非必需）。
  3. 方案 3（備援，需嚴管）DuckDNS + Let's Encrypt：安裝 DuckDNS Add-on 自動更新網域與憑證；於路由器只轉發 443 到反向代理，不要直接開 8123；HA 啟用 IP 封鎖與登入失敗鎖定。
  4. 啟用 HA 雙因素驗證（2FA）（Allen、Ann 皆設）。
  5. 設定 http: 的 ip_ban_enabled 與 login_attempts_threshold；使用 VPN 時可加 trusted_proxies 白名單。
⚠︎
既然核心訴求是安全，請避免方案 3 的對外開 port，優先 Tailscale。原設計的「固定 IP + 對外 8123」不建議。

驗收

  • 關閉家中 WiFi 用行動網路仍能安全連入 HA
  • 路由器對外 port 轉發清單為空（採 VPN 時）
  • 兩位使用者皆已啟用 2FA
P4

設備整合（逐子系統）

半天–1 天
目標：把 C 章的設備逐一納入 HA，先求「單獨可控」，再談自動化。

建議整合順序

  1. Philips Hue：設定 → 裝置與服務 → 新增 Philips Hue → 按 Bridge 配對鈕。確認 22 燈、Tap、Dimmer、Motion 皆出現；於 HA 分配區域。
  2. Zigbee2MQTT（Aqara 窗簾 + 任何原生 Zigbee 感測）：USB 協調器插上 Mac mini → UTM 設定將該 USB 裝置透傳給 VM → Z2M Add-on 指定序列埠 → permit join → 配對 Aqara C3。校正窗簾行程（0–100%）。
    替代：用 Aqara Hub M3 走 Matter，於 HA 與 Apple Home 同時加入。
  3. Roborock：新增 Roborock 整合（帳號配對），取得吸塵器實體與地圖、相機快照實體。
  4. TP-Link Tapo：新增 TP-Link Tapo 整合，加入 P306 各插座；為電鍋/淨水器/投影機等設「用電量」感測。
  5. Sony Bravia：新增 braviatv 整合（電視需開啟並輸入 PIN）。同時於電視開 AirPlay/HomeKit。
  6. 空調（擇一）：(a) HACS 安裝 panasonic_cc 用 Comfort Cloud 帳號（雲端）；或 (b) IR 閘道整合 + 學習遙控碼做本地控制。三台皆建立 climate.* 實體。
  7. 音訊/影音：Bose 以 AirPlay/媒體播放器加入；OVO 投影機以 IR/插座控制。
✦
每加一個子系統就單獨測試開關一次並建立快照。全部設備可控後再進入 Apple Home / AI / 場景。

驗收

  • Hue 22 燈、Aqara 窗簾、掃地機、Tapo 插座、電視、三台空調皆能在 HA 手動控制
  • 所有實體已分配正確區域與友善名稱
  • 窗簾開合百分比已校正
P5

Apple Home（HomeKit）整合

1 hr
目標：讓 iPhone「家庭」App 與 HomePod Siri 能操作全屋，HomePod 承擔語音入口與播報。

步驟

  1. HA 新增 HomeKit Bridge 整合；用「entity/domain 篩選」只匯出要給 Siri 控制的實體（燈、窗簾、空調、電視、部分插座），避免把 300 多個實體全丟進 Apple Home。
  2. iPhone 家庭 App → 加入配件 → 掃 HA 產生的 HomeKit 配對 QR/代碼。
  3. 在家庭 App 建立房間並把配件歸位（對應玄關/客餐廳/主臥/次臥…），指派 HomePod（客廳）與 HomePod mini（主臥）到對應房間。
  4. 設定 HomePod 為家庭中樞（Home Hub），讓 Apple 端自動化與遠端可用。
  5. 測試 Siri：「嘿 Siri，把客廳燈調暗」「打開主臥窗簾」「客廳冷氣 24 度」。
  6. （播報）設定 HA 對 HomePod 的 TTS/通知路徑：可經 AirPlay 媒體播放器或 Apple 捷徑觸發，用於場景語音回饋。
ℹ︎
採 Matter 的設備（如 Aqara Hub M3、部分新品）可同時直連 Apple Home 與 HA，多一條備援路徑；但主自動化仍集中在 HA 以維持單一大腦。

驗收

  • iPhone 家庭 App 可見並控制精選配件
  • HomePod Siri 能語音控制燈/窗簾/空調
  • HomePod 已設為家庭中樞、房間歸位正確
P6

本地 AI 語音（Hermes Agent 管線）

2–3 hr
目標：在 M4 上以 Metal 加速跑本地 LLM，串成「聽懂中文 → 推理意圖 → 呼叫 HA 服務 → 中文回覆」的 100% 本地語音管家。

步驟

  1. Ollama（macOS 原生，Metal）：
    brew install ollama
ollama serve            # 背景服務（設為登入啟動）
ollama pull hermes3     # NousResearch Hermes 3，具工具呼叫能力 = Hermes Agent
    讓 Ollama 監聽區網（OLLAMA_HOST=0.0.0.0）以便 VM 內的 HA 連得到。
