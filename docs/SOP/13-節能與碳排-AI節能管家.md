# 13 · 節能與碳排：AI 節能管家

> 目標：把「節能省碳」做成系統的**最高設計目標**（憲章 VI），而且只用**一個 AI 助理（Hermes 節能管家）**做所有節能決策——住戶永遠只需要對一個對象說「省一點」或「這次不要省」。
> 先決條件：03 章（含本章新增的 §3.8 用電量測）、05 章 Hermes、06 章情境。完成判準：§13.9。

## 13.1 三條原則怎麼落到系統裡

| 原則 | 系統落實 | 在哪驗證 |
|---|---|---|
| **(1) 在地執行，機敏資料不外洩** | 語音 STT/LLM/TTS 全在 Mac mini；Hermes 預設大腦 `ollama`（本地）；Grok 雲端只是**選配且預設關閉**，開啟時只送文字、不送語音與錄音，且後台會顯示警示；用電數據、在家/不在家、睡眠狀態只存在 HA 與 Hermes SQLite，不上雲；LINE/Telegram 只收指令與回覆文字，不推送感測器原始資料 | 08 章 A5 埠掃描；附錄 A.8 資料流清單 |
| **(2) 金鑰不進 GitHub** | 全部密鑰只在 `secrets.yaml` / `.env` / launchd 環境變數；`.gitignore` 已排除 `bluemagpie/.env`、`config/`、`data/`、`backups/`；推送前跑 `tools/check_secrets.py`（§13.8）；手冊內出現的 token 一律是 `xai-...`、`eyJhbGci...` 佔位 | §13.8 掃描結果為 0 |
| **(3) 節能省碳最高目標，一個 AI 助理** | Hermes 多了 `energy` 模組：**每一個**會動到空調/燈光/家電的計畫，執行前都經過「節能守門」修正；HA 只做量測與反射動作；35 個情境各有節能規則（§13.6）；每天 21:30 報告用電與碳排 | §13.9 |

## 13.2 架構：量測在 HA、決策在 Hermes

```
 Shelly EM（總表 CT）──┐
 Aqara 計量插座 ×N ────┼─► HA（utility_meter 日/月、碳排、尖峰時段、全屋無人）
 Hue Motion 照度 ──────┘        │  反射動作：無人 20 分關空調、開窗關冷氣、尖峰提醒、白天調暗
                                │
   任何語音/情境計畫 ──► Hermes ──► energy.clamp（守門：溫度下限、亮度上限、除濕優先）──► 執行
                                └─► energy.report（每日 21:30 / 週一週報 / 隨問隨答）
```

為什麼決策只放 Hermes：

- **一個開關管全部**：住戶說「這次不要省」→ `energy.pause_guard` 兩小時，35 個情境同時放寬；不必逐個情境改條件。
- **只收緊、不放寬**：守門只會把 24 度改 27 度、100% 改 40%，不會反過來；情境本身的安全邏輯（鎖、警報、SOS）完全不經守門。
- **可解釋**：每次修正都寫進 tx log（`energy s2 節能：冷氣最低 27 度`）並附在回覆句尾，住戶知道為什麼。

## 13.3 用電量測硬體（03 章 §3.8）

| 量什麼 | 設備 | 本地？ | HA 實體 |
|---|---|---|---|
| 全屋總用電 | Shelly EM + 50A CT 夾（裝在配電箱總開關後；請水電師傅 30 分鐘） | 是（Wi-Fi，原生 HA 整合） | `sensor.home_power`、`sensor.home_energy_total` |
| 三台冷氣 | 冷氣專用迴路各一顆 Shelly 1PM 或 Aqara 智慧插座（計量版，20A） | 是（Zigbee） | `sensor.ac_living_energy` …（kWh 累計） |
| 電視影音 / 音響 / 次臥書桌 | Aqara 智慧插座 SP-EUC01 ×3 | 是 | `switch.tv_plug`、`switch.audio_plug`、`switch.second_desk_plug` + `sensor.*_energy` |
| 冰箱、洗烘、Mac mini | Aqara 智慧插座（**只量不切**：s00_energy 的待機群組不含這三個） | 是 | `sensor.fridge_plug_energy`、`sensor.laundry_plug_energy`、`sensor.server_plug_energy` |
| 自然光 | Hue Motion 附照度（已有） | 是 | `sensor.living_illuminance` |

Z2M friendly_name 與實體對照寫進 03 章 §3.3 的表；`utility_meter` 會自動產生 `*_today` / `*_month`。

HA 內建 **能源儀表板**（設定 → 儀表板 → 能源）：電網消耗選 `sensor.home_energy_total`，個別裝置加上面的 `sensor.*_energy`；它會畫出每小時與每日分項圖，本章的報告數字與它一致。

## 13.5 Hermes 節能模組（v0.4）

檔案：`hermes/hermes/energy.py`、`config/energy.yaml`、`config/tools/energy.yaml`。

### 守門規則（`energy.clamp`，每一步執行前）

| 工具 | eco（預設） | normal | comfort |
|---|---|---|---|
| `climate.set` 冷氣溫度下限 | **27 °C**（尖峰 28） | 26（尖峰 27） | 24 |
| `climate.set` 暖氣上限 | 20 | 22 | 24 |
| 除濕取代冷氣 | 室內 RH < 65% 且室溫 ≤ 28 → `dry` | RH < 60% | 不做 |
| 風速 | 未指定 → `auto` | auto | auto |
| `light.set` 亮度上限 | 70%；白天（照度 ≥ 300 lx）客廳/次臥 **40%** | 100% / 60% | 不限 |
| `light.activate_scene` Focus | 改 Welcome | 不改 | 不改 |
| 無人多久關 | 20 分 | 30 分 | 60 分 |

修正會附在回覆：「好了。節能：冷氣最低 27 度。」住戶不喜歡 → 說「這次不要省」。

### 工具

| 工具 | 說什麼會觸發 | 做什麼 |
|---|---|---|
| `energy.report` | 「今天用了幾度」「這個月電費」「省了多少」 | 讀 utility_meter 與基準 → 「今天用電 9.4 度，約 4.5 公斤碳排，比基準省了 22%；最耗電是冷氣客廳 5.1 度、電視影音 1.2 度。冷氣佔一半以上，設定溫度每高一度約省百分之六。」 |
| `energy.set_mode` | 「今天宴客」「切舒適模式兩小時」 | 改 `input_select.energy_mode` 並啟動 timer，到期回 eco |
| `energy.pause_guard` | 「這次不要省」「別管節能」 | 暫停守門 120 分鐘（只影響 Hermes 守門，HA 反射動作照舊） |
| `energy.idle_sweep` | 「我要出門了」「睡前巡一下」 | 呼叫 `script.energy_idle_sweep`：關空調/燈、切待機群組（冰箱/伺服器永不切） |

### 設定重點（`config/energy.yaml`）

- `carbon_kg_per_kwh: 0.474`：台電 2024 公告值；每年 6 月查台電「電力排碳係數」更新。
- `tariff`：住商型簡易時間電價二段式（夏月 6–9 月平日 09–24 尖峰；非夏月 06–11、14–24；週末全離峰）。**只用來避峰與報告**，不算電費（電費以台電帳單為準）。
- `sensors.devices`：有幾個計量插座填幾個，報告會列前三名。

## 13.8 金鑰不進 GitHub：推送前掃描

`tools/check_secrets.py`（已放在 repo 根目錄 `tools/`）：

```bash
python3 tools/check_secrets.py            # 掃 git 追蹤中的檔案；找到就非 0 結束
git config core.hooksPath .githooks       # 啟用 pre-push：推送前自動跑一次
```

規則：偵測 `xai-`、`sk-`、`ghp_`、`eyJhbGci`（JWT）、`AKIA`、`-----BEGIN`、LINE channel secret 長 hex、Telegram token `數字:英數` 等；佔位符（`xai-...`、`<token>`）會排除。`.env`、`secrets.yaml`、`config/`、`data/`、`backups/` 本來就不在 git 內；請不要用 `git add -f` 強加。
