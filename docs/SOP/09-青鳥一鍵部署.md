# 09 · 青鳥 · 台灣藍鵲：一鍵 Docker 部署與後台

> 目標：把 00–08 章手動建置的成果變成產品：一個資料夾 `bluemagpie/`、一條 `install.sh`、一個後台 `:9000`，在 Linux / macOS / Windows 的 Docker 上跑起整套（Home Assistant、Mosquitto、Zigbee2MQTT、Whisper、Piper、Ollama、Hermes），所有系統參數與接口都在後台設定，熱備雙節點由後台負責。
> 程式位置：`SmartHome/bluemagpie/`（與 SOP 共用 35 情境 packages 與 Hermes 程式）。

## 9.1 產品架構

```
┌──────────────── bluemagpie/（一個資料夾）────────────────┐
│ install.sh ──► docker compose up -d                        │
│                                                            │
│  magpie-admin :9000  ◄─ 瀏覽器：設定 / 套用 / 健康 / 備份  │
│     │ 寫設定檔、重啟容器（docker.sock）、每小時備份推送     │
│     ▼                                                      │
│  config/{homeassistant,mosquitto,zigbee2mqtt,hermes}/      │
│     │                                                      │
│  homeassistant :8123 ─ mosquitto :1883 ─ zigbee2mqtt :8099 │
│  whisper :10300 ─ piper :10200 ─ ollama :11434 ─ hermes :8800│
└────────────────────────────────────────────────────────────┘
        │ tcp 6638                         │ 每小時 tar.gz（HTTP + shared secret）
   SLZB-06 Zigbee 協調器             副節點 bluemagpie/（standby）
```

| 面向 | HAOS 手動版（02–07 章） | 青鳥 Docker 版（本章） |
|---|---|---|
| HA | HAOS VM（UTM）+ 附加元件 | `ghcr.io/home-assistant/home-assistant` 容器；無 Supervisor，附加元件改為同層容器 |
| 語音 | macOS 原生 launchd | Whisper / Piper 容器；Ollama 容器或主機原生（macOS Metal） |
| Hermes | macOS venv + launchd | `bluemagpie/hermes` 容器，設定由後台產生 |
| Zigbee | SLZB-06 或 USB 直通 VM | SLZB-06（跨平台）；Linux 可 USB |
| 備份／熱備 | HA 內建備份 + `hassio.*` + standby package | 後台內建：打包 `config/ data/`、推送、接收、還原、監看、自動接手 |
| 參數 | 散在 secrets.yaml、附加元件設定、plist | 後台一個畫面；「套用」一次產生全部 |
| 35 情境 | 手動複製 packages | 套用時自動安裝（`provision/homeassistant/packages`） |

兩處因 Docker 版沒有 Supervisor 而改寫的 package：`s23`（改呼叫後台 `rest_command.magpie_backup`）、`s00_node`（角色由後台寫入 `input_text.magpie_role`）。其餘 35 情境 YAML 與 06 章完全相同。

## 9.2 安裝（主節點）

```bash
# Linux（含 Mac mini 跑 Linux、N100、樹莓派 5）或 macOS
cd SmartHome/bluemagpie
bash install.sh
```

腳本做的事：檢查/安裝 Docker → 產生 `.env`（隨機後台密碼）→ 建立 `config/ data/ backups/` → Linux 額外套 `docker-compose.host.yml`（HA host 網路）→ `docker compose up -d --build` → 印出後台與 HA 網址。macOS 會自動停掉容器版 Ollama，提示安裝主機原生 Ollama。

Windows：PowerShell 執行 `.\install.ps1`（需先裝 Docker Desktop + WSL2）。

## 9.3 後台設定流程（第一次）

| 步驟 | 後台頁面 | 要填 |
|---|---|---|
| 1 | 網站與節點 | 系統名稱、時區、角色 `primary`、本機區網 IP、網路模式（Linux `host` / Docker Desktop `bridge`）、改後台密碼 |
| 2 | 先去 HA | `http://<IP>:8123` 完成 HA 初始化（帳號、家的位置）→ 個人 → 安全性 → 建立長效權杖 |
| 3 | Home Assistant | 貼權杖；外部網址；備份加密密碼留空自動產生；勾「安裝 35 情境 packages」 |
| 4 | MQTT | 帳號 `mqtt`，密碼留空自動產生 |
| 5 | Zigbee | `tcp` + SLZB-06 IP `192.168.0.25`、埠 6638、`ember`、頻道 15 |
| 6 | 語音 | Whisper `small`、Piper `zh_CN-huayan-medium`；macOS 選 Ollama 來源 `host`、網址 `http://host.docker.internal:11434` |
| 7 | Hermes | `confirm_all`、深夜 23:00–07:00、自選股、停損 8% |
| 8 | 通知對象 | 兩支手機的 notify 服務名稱（Companion App 登入後 HA 會產生） |
| 9 | 遠端存取 | DuckDNS 網域與 token（NGINX/憑證在 Docker 版建議用主機層 Caddy 或 Tailscale，見 §9.7） |
| 10 | 熱備 | 另一節點後台網址、共用密鑰留空自動產生（之後複製到副節點） |
| 11 | **套用並重啟相關服務** | 後台產生：`mosquitto.conf`+`passwd`、Z2M `configuration.yaml`（保留既有 network_key）、Hermes 三個 yaml、HA `secrets.yaml`+`packages/s00_magpie.yaml`+35 情境、`.env`；重啟 mosquitto / zigbee2mqtt / hermes / homeassistant |

套用後：後台 **OpenClaw 語音** 頁 → 「下載 LLM 模型」→ 「一鍵串接到 Home Assistant」（自動新增 Wyoming ×2、Ollama→Hermes 整合、建立並預設 Assist 管線「OpenClaw」）。再回 HA：設定 → 整合 → 新增 MQTT（`mosquitto` / `host.docker.internal`、帳密同後台）、Local IP，以及 03 章的 Hue / Panasonic / Roborock / Apple TV / Companion；Ollama 整合的「控制 Home Assistant」設為不控制。HomePod 進聲路徑（Siri 捷徑 webhook）照 04 章 §4.7。

## 9.4 後台功能

| 頁面 | 功能 |
|---|---|
| 總覽與健康 | 8 個容器狀態 + HTTP 探測（HA API、Hermes、Z2M、Ollama、另一節點）；每個容器可重啟/停止/啟動；事件；容器記錄 200 行 |
| 各設定頁 | 依 `settings.py` 的 SCHEMA 自動產生表單；密碼欄遮罩；「儲存」只存、「套用」才渲染+重啟 |
| OpenClaw 語音 | 四元件狀態（Whisper / Piper / Ollama+模型 / Hermes）與 HA 端 stt/tts/對話實體；下載 LLM 模型；**一鍵串接到 HA**（config flow + Assist 管線） |
| 備份與熱備 | 立即備份並推送；備份清單（本機／主節點推送）；一鍵還原；手動接手／回切 |

後台 API（供 HA `rest_command` 或腳本）：`GET /api/health`、`POST /api/apply`、`POST /api/backup/run`（Basic 或 `X-Magpie-Secret`）、`POST /api/backup/receive`、`POST /api/backup/restore`、`POST /api/cluster/promote|demote`、`GET /api/logs/{service}`。

後台無法做的（需在主機）：改埠號／模型／profile 後 `docker compose up -d`；升級映像 `docker compose pull && up -d`。

## 9.5 副節點與熱備

```bash
# 副節點（HA Black 或任何第二台）
bash install.sh standby          # 容器全部建立，但 HA / Z2M / Hermes 停止
```

副節點後台：角色 `standby`、另一節點網址填主節點 `http://192.168.0.11:9000`、共用密鑰貼主節點產生的那組 → 套用。

| 時機 | 主節點後台 | 副節點後台 |
|---|---|---|
| 平時 | 每小時 :05 打包 `config/ data/`（排除 HA 資料庫 WAL、圖卡、log）→ `POST peer/api/backup/receive` | 每 30 秒 `GET peer/api/health/self`；保留最近 30 份 `recv_*.tar.gz` |
| 主節點失聯 4 分 50 秒 | — | 推播「即將接手」 |
| 失聯 5 分鐘且 auto_promote | — | 角色改 primary → 套用 → 還原最新 `recv_*` → 啟動 HA / Z2M / Hermes（Z2M 連 SLZB-06）→ 推播「已接手」 |
| 主節點修好 | 從副節點備份清單還原最新一份（副節點先按「立即備份」）→ 啟動 | 按「回切為副節點」（停 HA / Z2M / Hermes、角色改 standby） |

HA 長效權杖在 `.storage` 內，隨備份到副節點，所以 Hermes 與後台在接手後不需換 token。Hermes 的 `ha.urls` 由後台寫成「主節點 → 副節點」兩個位址，自動切換。

## 9.6 跨平台注意事項

| 平台 | 網路模式 | Zigbee | Ollama | mDNS 探索（HomePod / Hue / Apple TV） |
|---|---|---|---|---|
| Linux | `host`（install.sh 自動） | SLZB-06 或 USB（`docker-compose.host.yml` 開 devices） | 容器（NVIDIA 可加 GPU）| 完整 |
| macOS | `bridge` | SLZB-06 | **主機原生**（Metal） | 不完整：整合時用 IP 手動加 |
| Windows | `bridge` | SLZB-06 | 容器（NVIDIA 可加 GPU）或主機原生 | 不完整：同上 |

bridge 模式下 Companion App 內部網址填主機 IP:8123；Hermes / 後台互連用容器名稱（後台已自動依網路模式切換 `hermes` ↔ `host.docker.internal`）。

## 9.7 遠端存取（Docker 版）

沒有 HAOS 附加元件，建議二選一：
- **Tailscale**（最省事）：兩台主機各 `tailscale up`；Companion App 用 MagicDNS 名稱；不需開埠。
- **Caddy**（要 https 網址）：主機層 `caddy reverse-proxy --from AllenandAnn.duckdns.org --to localhost:8123`，自動 Let's Encrypt；路由器 443 → 主節點。DuckDNS 更新可用 `docker run linuxserver/duckdns`。

## 9.9 已知限制（v0.1）

- 後台不能重建容器（埠／profile 變更要在主機 `docker compose up -d`）。
- 副節點接手時 helpers 狀態最多落後 1 小時（與 07 章相同）。
- 443 入口不會自動漂移；接手期間外部連線靠 Tailscale。
- 後台為單一密碼 Basic Auth，請只在區網或 VPN 內開放 9000 埠。
