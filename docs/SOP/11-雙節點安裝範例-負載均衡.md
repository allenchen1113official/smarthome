# 11 · 安裝範例：Mac mini M4 主節點 + HA Black 副節點，軟體負載均衡雙活

> 目標：兩台都開機、都在服務。前面放一個軟體負載均衡（HAProxy + keepalived 虛擬 IP），**無狀態服務雙活分流**（Whisper、Piper、Hermes），**Home Assistant 主從自動切換**（主節點掛掉 LB 秒級導向副節點，後台同時自動接手 Zigbee 與情境）。全程用 `bluemagpie/` 與 `bluemagpie/lb/`。
> 做不到的先講：HA 本身無叢集，兩台 HA 不能同時擁有 Zigbee 與狀態；所謂 active-active 是入口與無狀態服務雙活、HA 核心主從。

## 11.1 拓樸

```
                     家內區網 192.168.0.0/24
   手機 / 平板 / Siri 捷徑 / LINE webhook ──► VIP 192.168.0.100 ◄── keepalived VRRP（誰活著誰持有）
                                                   │
                     ┌─────────────────────────────┴─────────────────────────────┐
             LB-A（Mac mini 上的 Alpine 小 VM，priority 150）        LB-B（HA Black 原生，priority 100）
             HAProxy：相同設定                                       HAProxy：相同設定
                     │                                                         │
      ┌──────────────┴──────────────┐                        ┌─────────────────┴──────────────┐
  節點 A · Mac mini M4 · 192.168.0.88（主）                節點 B · HA Black N100 · 192.168.0.12（副）
  Docker Desktop：HA、Z2M、Hermes、bot、Whisper、Piper     Docker host 網路：Whisper、Piper、Hermes、admin、mosquitto
  主機原生 Ollama（Metal）                                  HA / Z2M / bot 容器存在但停止 → 接手時由後台啟動
                     └────────────── tcp 6638 ──► SLZB-06 Zigbee 協調器 ◄── 接手後 ─────────┘
```

| 服務 | 分流方式 | 說明 |
|---|---|---|
| Home Assistant :8123 | 主從（A 優先，B `backup`） | WebSocket 長連線；健康檢查 `GET /api/` 期望 401 |
| 後台 admin :9000 | 主從 | |
| Hermes :8800 | **雙活**（roundrobin + 來源 IP 黏著 15 分鐘） | 黏著讓「要我…嗎？→ 好」落在同一節點 |
| Whisper :10300 / Piper :10200 | **雙活**（leastconn） | HA 的 Wyoming 整合指向 VIP，兩台一起算 |
| Ollama :11434 | 只有 A | N100 跑不動 8B 模型 |
| bot :8900（LINE webhook） | 主從 | Telegram polling 只在活著的那台跑 |

## 11.3 節點 A（Mac mini M4，主）

```bash
cd ~/SmartHome/bluemagpie
bash install.sh                     # macOS：bridge 網路、停容器版 Ollama 與 Whisper
brew install ollama && brew services start ollama && ollama pull qwen3:8b
# 主機原生 mlx-whisper（Metal）：照 04 章 §4.2、§4.4 裝 venv 與 launchd（監聽 0.0.0.0:10300）
```

後台 `http://192.168.0.88:9000`：
- 網站與節點：角色 `primary`、區網 IP `192.168.0.88`、網路模式 `bridge`
- 語音：STT 引擎來源 `host`、Ollama 來源 `host`、LLM 模型 `qwen3:8b`（HA Black 那邊兩者都 `container`，LB 的 whisper 雙活仍成立：A 是 mlx-whisper、B 是 faster-whisper，都是 Wyoming :10300）
- 熱備：另一節點 `http://192.168.0.12:9000`、**VIP `192.168.0.100`**、共用密鑰留空自動產生（記下來）
- 語音：Ollama 來源 `host`
- 其餘頁面照 09 章 → **套用**；OpenClaw 頁 → 一鍵串接（Wyoming 會指向 VIP:10300/10200）

HA：設定 → 系統 → 網路：內部網址 `http://192.168.0.100:8123`（VIP）。Companion App 內部網址同 VIP。

## 11.4 節點 B（HA Black，副）

```bash
cd ~/SmartHome/bluemagpie
bash install.sh standby             # Linux：host 網路；HA / Z2M / Hermes / bot 建立後停止
docker compose start hermes         # 副節點也跑 Hermes，讓它雙活（它只需連 VIP:8123 與 Ollama VIP:11434）
```

後台 `http://192.168.0.12:9000`：角色 `standby`、區網 IP `192.168.0.12`、網路模式 `host`、另一節點 `http://192.168.0.88:9000`、VIP `192.168.0.100`、共用密鑰貼 A 的 → 套用。
Whisper / Piper 在副節點本來就常駐（無 profile），裝完即加入雙活。

⚠️ 副節點的 Hermes 要連 Ollama：後台「語音」Ollama 來源選 `host`、網址填 `http://192.168.0.100:11434`（走 VIP 到 Mac mini）。

## 11.5 LB-B（HA Black 原生）

```bash
cd ~/SmartHome/bluemagpie/lb
sudo VIP=192.168.0.100 NODE_A=192.168.0.88 NODE_B=192.168.0.12 PRIORITY=100 IFACE=$(ip route | awk '/default/{print $5; exit}') sh install-lb.sh
sudo systemctl status haproxy keepalived --no-pager | head
```

## 11.6 LB-A（Mac mini 上的 Alpine 小 VM）

macOS 沒有 VRRP，用 UTM 建一台 Alpine（512 MB RAM、1 vCPU、橋接 en0）：

1. 下載 Alpine virt ISO（aarch64）→ UTM → Virtualize → Linux → 記憶體 512 MB、磁碟 2 GB、Network **Bridged (en0)**、名稱 `magpie-lb`。
2. 開機 → `setup-alpine`（主機名 `magpie-lb`、eth0 DHCP、安裝到 vda、sys 模式）→ 重開 → 路由器 DHCP 保留 `192.168.0.13`。
3. 把 `bluemagpie/lb/` 複製進 VM（`scp -r lb root@192.168.0.13:/root/`），執行：

```sh
apk add --no-cache openssh git
cd /root/lb && VIP=192.168.0.100 NODE_A=192.168.0.88 NODE_B=192.168.0.12 PRIORITY=150 IFACE=eth0 sh install-lb.sh
```

4. UTM：VM 設定「開機自動啟動」並加入 macOS 登入項目（同 02 章的 HAOS 作法，`utmctl start magpie-lb`）。

LB-A priority 150 > LB-B 100，所以平時 VIP 在 Mac mini 側；Mac mini 整台掛掉 → VIP 1 秒內跳到 HA Black 側。

## 11.7 驗證（雙活）

```bash
# 1) VIP 在誰身上
ip addr | grep 192.168.0.100            # 在 LB-A 應看到；LB-B 沒有
# 2) HAProxy 統計頁：兩台都看得到後端綠燈
open http://192.168.0.13:8404/stats     # mac/black：ha_nodes（black 為 backup）、whisper/piper 兩台 UP、hermes 兩台 UP
# 3) 透過 VIP 存取
curl -s -o /dev/null -w "%{http_code}\n" http://192.168.0.100:8123/api/      # 401（HA 活著）
curl -s http://192.168.0.100:8800/v1/health                                   # 連打 5 次，統計頁 hermes 兩台 session 數都在增加
# 4) Whisper 雙活：HA Assist 連續講 6 句，統計頁 whisper_tcp 的 mac / black 各約一半
```

## 11.8 故障演練

| 演練 | 動作 | 預期 | 復原 |
|---|---|---|---|
| A. HA 容器掛 | Mac mini：`docker compose stop homeassistant` | ≤ 6 秒 HAProxy 把 ha_nodes 切到 black（此時 black 的 HA 未啟動 → 503）；5 分鐘後副節點後台自動接手（還原備份、啟動 HA/Z2M/bot），VIP:8123 恢復；Hermes 走 VIP 無感 | `docker compose start homeassistant` → 09 §9.5 回切 |
| B. Mac mini 整台關機 | 關機 | VIP 1 秒跳到 LB-B；Whisper/Piper 只剩 black 服務；Ollama 不可用 → Hermes 退回…（無 Grok 時回「等我一下」；有 Grok 接口則改走雲端）；5 分鐘後副節點接手 HA | 開機 → 回切；VIP 自動回到 LB-A |
| C. LB-A 掛（VM 關） | `utmctl stop magpie-lb` | VIP 跳 LB-B，服務不中斷（後端都還在 A） | 開 VM，VIP 回 A |
| D. HA Black 整台關機 | 關機 | 無感：VIP 在 A，whisper/piper/hermes 的 black 後端標 DOWN | 開機自動歸隊 |
| E. 副節點誤判接手 | 在 B 後台把 `auto_promote` 關掉重做 A | 只推播「接手／取消」按鈕，不自動接手 | — |

每次演練看三個地方：HAProxy 統計頁、兩台後台「事件」、手機推播。

## 11.9 設定調整提醒

- Companion App、Siri 捷徑 webhook、LINE webhook 反向代理、Hermes `ha.urls` 第一項、Wyoming 整合：全部指 **VIP**。
- 不要把 LB 的 8123 綁在實體 IP，只綁 VIP（設定檔已如此），避免與節點本機的 HA 埠衝突。
- keepalived 若要「主節點回來不搶回 VIP」加 `nopreempt`；本範例採搶回（priority 高者持有），因為 Mac mini 側的服務較完整。
- 副節點記憶體：N100 8 GB 跑 HAOS 容器 + Z2M + Hermes + Whisper small + Piper 約 3 GB，足夠；不要在副節點啟動 Ollama。
