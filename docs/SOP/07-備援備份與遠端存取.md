# 07 · 熱備雙節點、備份與遠端存取

> 目標：Mac mini M4 為**主節點**、HA Black 為**副節點**，兩台 24/7 開機。主節點每小時把設定推到副節點；主節點失聯 5 分鐘，副節點**自動**還原最新設定、接管 Zigbee 網路、啟動全部情境並推播兩人；手機在家內外都能連到任一節點。主節點修好後由你手動回切。
> 完成判準：§7.9。

## 7.1 架構

```
            Hermes / OpenClaw（Mac mini .8，只有一份）
                 │ HA REST：主 .18 → 失敗自動改 .28
   ┌─────────────▼────────────┐          ┌─────────────────────────┐
   │ 主節點 Mac mini M4        │  每小時   │ 副節點 HA Black N100     │
   │ HAOS VM .18（UTM）        │ ───────► │ HAOS .28（實體機）        │
   │ Mosquitto · Z2M(running)  │ 設定備份  │ Mosquitto · Z2M(stopped) │
   │ 35 情境 · NGINX · DuckDNS │ 03:00 全備│ watchdog · Samba · Tailscale│
   └─────────────┬────────────┘          └───────────┬─────────────┘
                 │ tcp://.25:6638                      │ 接手後才連
                 └──────────► SLZB-06（PoE Zigbee 協調器 .25）◄──────┘
                              同一時間只接受一個 Z2M 連線
```

和原設計的差異（都已反映到 01/02 章與 packages）：

| 項目 | 原設計 | 熱備版 |
|---|---|---|
| Zigbee 協調器 | USB Stick 直通 VM，接手要拔插 | **SLZB-06**（PoE、Zigbee over TCP），兩台 Z2M 設定相同，誰啟動誰接管 |
| 副節點狀態 | 待命、整合停用 | 24/7 開機，只跑「監看 + 接收備份」的最小 HA，不跑任何情境 |
| 同步 | 每晚快照 | 每晚全備 + **每小時設定備份**（helpers 狀態最多落後 1 小時） |
| 接手 | 手動 15 分鐘 | 失聯 5 分鐘自動還原並啟動，約 4 分鐘完成；可改成「先推播、你按鈕才接手」 |
| 外部入口 | 443 → .18 | 443 仍 → .18；另加 **Tailscale** 兩台都裝，手機同時登兩個伺服器 |
| Hermes | 只認 .18 | `ha.urls` 列兩個節點，連不上主節點自動改副節點（token 隨備份還原，兩邊通用） |

HAOS 沒有叢集功能，所以這是「設定鏡像 + 自動升級」，不是真正雙活。副節點平時**不能**啟用任何情境或雲端整合，否則會和主節點互打（燈被開兩次、Comfort Cloud 互踢登入）。

## 7.2 SLZB-06 網路 Zigbee 協調器

1. 接 PoE 到路由器 LAN 埠（或用附的 USB 供電 + 網路線），路由器 DHCP 保留 `192.168.0.25`。
2. 瀏覽器開 `http://192.168.0.25` → 模式選 **Zigbee Coordinator (Ethernet)**，記下埠 `6638`；韌體更新到最新。
3. 主節點 Z2M 設定（02 章 §2.7 已改為此版）：

```yaml
serial:
  port: tcp://192.168.0.25:6638
  adapter: ember        # SLZB-06 為 EFR32MG21；SLZB-06M 用 zstack
  baudrate: 115200
advanced:
  channel: 15
  network_key: GENERATE  # 第一次啟動後 Z2M 會把實際金鑰寫回設定檔，備份會帶到副節點
```

4. 若已經用 USB Stick 配好設備：Z2M → Settings → Tools → **Backup**，換 SLZB-06 後用 **Restore** 把網路搬過去（同廠牌晶片可直接遷移，否則需重配對）。
5. 用 USB 延長線那段從此不需要；02 章 §2.4 的 USB 直通改為選配。

## 7.3 副節點 HA Black 準備（只做一次）

1. 安裝 HAOS generic-x86-64，DHCP 保留 `192.168.0.28`，初始化帳號 `allen`（之後會被主節點備份覆蓋，無所謂）。
2. 附加元件：**Samba share**（使用者 `ha`、`allow_hosts` 含 `192.168.0.0/24`）、**Terminal & SSH**、**Mosquitto broker**（啟動）、**Zigbee2MQTT**（安裝、設定同主節點含 `tcp://192.168.0.25:6638`，**不要啟動**、取消「開機時啟動」）、**Tailscale**（§7.7）。
3. BIOS：Power Limit 10 W、Restore on AC Power Loss = Power On、機身立放留 5 cm；只跑 HA 的 N100 不會再過熱。
4. 兩支手機 Companion App → 伺服器 → 新增 `http://192.168.0.28:8123`（名稱「備援」），各登入一次：副節點的推播才送得出去。
5. 把 `ha-config/standby/standby_node.yaml` 放到副節點 `/config/packages/`，`configuration.yaml` 加 `homeassistant: packages: !include_dir_named packages`，重新啟動。它只含：ping 監看、兩段式接手、回切輔助。

```yaml
# file: standby/standby_node.yaml（只放在副節點 HA Black）
input_boolean:
  auto_promote:
    name: 自動接手（關閉＝失聯只推播，要你按鈕才接手）
    initial: on
    icon: mdi:swap-horizontal-bold
  promoted:
    name: 本機已接手為主節點
    initial: off
    icon: mdi:crown

binary_sensor:
  - platform: ping
    name: macmini_ping
    host: 192.168.0.18       # 主節點 HAOS VM
    count: 2
    scan_interval: 30
  - platform: ping
    name: macmini_host_ping
    host: 192.168.0.8       # Mac mini 本體（用來分辨「VM 掛」還是「整台掛」）
    count: 2
    scan_interval: 30

shell_command:
  latest_backup_slug: "ls -t /backup/*.tar | head -1 | xargs -n1 basename | sed 's/\\.tar$//'"

notify:
  - name: both
    platform: group
    services:
      - service: mobile_app_allen_iphone
      - service: mobile_app_ann_iphone

script:
  promote_to_primary:
    alias: 接手為主節點（還原最新備份並啟動）
    mode: single
    sequence:
      - action: shell_command.latest_backup_slug
        response_variable: r
      - variables:
          slug: "{{ r.stdout | trim }}"
      - action: notify.both
        data: { message: "🛟 備援機開始接手：還原備份 {{ slug }}，約 4 分鐘後恢復控制。" }
      - action: input_boolean.turn_on
        target: { entity_id: input_boolean.promoted }
      # 還原 config + Z2M/Mosquitto 附加元件；還原後 HA 會自動重啟，之後由 s00_node 的「非主節點啟動」自動化接續
      - action: hassio.restore_partial
        data:
          slug: "{{ slug }}"
          homeassistant: true
          addons: [45df7312_zigbee2mqtt, core_mosquitto]
          password: !secret backup_password

automation:
  - id: standby_primary_lost
    alias: 備援：主節點失聯 5 分鐘
    mode: single
    triggers:
      - trigger: state
        entity_id: binary_sensor.macmini_ping
        to: "off"
        for: { minutes: 5 }
    conditions:
      - condition: state
        entity_id: input_boolean.promoted
        state: "off"
    actions:
      - action: notify.both
        data:
          message: >-
            🛟 主節點失聯 5 分鐘（{{ 'Mac mini 整台離線' if is_state('binary_sensor.macmini_host_ping','off') else '只有 HAOS 虛擬機離線' }}）。
            {{ '2 分鐘後自動接手，回覆「取消」可中止。' if is_state('input_boolean.auto_promote','on') else '按「接手」由備援機接管。' }}
          data:
            push: { interruption-level: time-sensitive }
            actions:
              - { action: STANDBY_PROMOTE, title: 接手 }
              - { action: STANDBY_CANCEL, title: 取消 }
      - if: "{{ is_state('input_boolean.auto_promote','on') }}"
        then:
          - wait_for_trigger:
              - trigger: event
                event_type: mobile_app_notification_action
                event_data: { action: STANDBY_CANCEL }
              - trigger: state
                entity_id: binary_sensor.macmini_ping
                to: "on"
            timeout: { minutes: 2 }
            continue_on_timeout: true
          - if: "{{ not wait.trigger }}"
            then:
              - action: script.promote_to_primary

  - id: standby_promote_button
    alias: 備援：推播按鈕「接手」
    triggers:
      - trigger: event
        event_type: mobile_app_notification_action
        event_data: { action: STANDBY_PROMOTE }
    conditions:
      - condition: state
        entity_id: input_boolean.promoted
        state: "off"
    actions:
      - action: script.promote_to_primary

  - id: standby_primary_back
    alias: 備援：主節點恢復（提醒回切）
    triggers:
      - trigger: state
        entity_id: binary_sensor.macmini_ping
        from: "off"
        to: "on"
        for: { minutes: 2 }
    actions:
      - action: notify.both
        data:
          message: "✅ 主節點 Mac mini 已恢復連線。{{ '備援機目前仍是主節點，請依 SOP 07 §7.6 手動回切。' if is_state('input_boolean.promoted','on') else '' }}"
```

## 7.4 主節點：每小時設定備份 + 每晚全備（情境 23）

主節點 HA：設定 → 系統 → 儲存空間 → 新增網路儲存空間 `standby`（SMB `192.168.0.28` 分享 `backup`、用途備份）。設定 → 系統 → 備份 → 設定自動備份：每天 03:00、保留 7 份、位置勾 **本機 + standby**、加密開啟，金鑰存進 `secrets.yaml` 的 `backup_password` **並抄一份貼在 HA Black 機身**（兩台 secrets.yaml 都要有同一個 `backup_password`）。

情境 23 的 package（已更新）每小時整點再做一次**只含設定的部分備份**到 standby：

```yaml
# packages/s23_nightly_backup.yaml（節錄）
  - id: s23_hourly_config_backup
    alias: 23 每小時設定備份到副節點
    triggers:
      - trigger: time_pattern
        minutes: 5
    conditions:
      - condition: state
        entity_id: input_boolean.s23_enabled
        state: "on"
    actions:
      - action: hassio.backup_partial
        data:
          name: "hourly_{{ now().strftime('%H') }}"
          homeassistant: true
          addons: [45df7312_zigbee2mqtt, core_mosquitto]
          location: standby
          compressed: true
          password: !secret backup_password
```

`hourly_00`…`hourly_23` 固定 24 個檔名循環覆蓋，副節點的 `/backup` 最多 24 份小時備 + 7 份全備（約 1–2 GB）。helpers 狀態（睡眠模式、班別、計數器）存在 `.storage/core.restore_state`，隨設定備份帶過去，所以接手後最多落後 1 小時。

## 7.5 主節點 packages 的「節點感知」（`s00_node.yaml`，兩台共用）

這個 package 隨備份一起到副節點，用 **Local IP** 整合判斷自己在哪台機器上跑，接手後自動做收尾：

```yaml
# file: packages/s00_node.yaml（主節點 packages 內，隨備份到副節點）
template:
  - binary_sensor:
      - name: is_primary_node
        unique_id: is_primary_node
        state: "{{ states('sensor.local_ip') == '192.168.0.18' }}"

automation:
  - id: s00_node_started_on_standby
    alias: 節點：在副節點啟動（接手收尾）
    mode: single
    triggers:
      - trigger: homeassistant
        event: start
    conditions:
      - condition: state
        entity_id: binary_sensor.is_primary_node
        state: "off"
    actions:
      - delay: { seconds: 60 }                      # 等整合載入
      - action: hassio.addon_start
        data: { addon: 45df7312_zigbee2mqtt }
        continue_on_error: true
      - action: input_boolean.turn_off
        target: { entity_id: input_boolean.s23_enabled }   # 副節點不再往自己備份
      - action: notify.both
        data:
          message: "🛟 備援機已接手：Zigbee 已接管、35 個情境運作中。語音退回 HA 基本模式（Hermes 若仍在線會自動改連本機）。"
          data: { push: { interruption-level: time-sensitive } }

  - id: s00_node_started_on_primary
    alias: 節點：在主節點啟動（確認 Z2M 運作）
    triggers:
      - trigger: homeassistant
        event: start
    conditions:
      - condition: state
        entity_id: binary_sensor.is_primary_node
        state: "on"
    actions:
      - delay: { seconds: 60 }
      - action: hassio.addon_start
        data: { addon: 45df7312_zigbee2mqtt }
        continue_on_error: true
```

前置：主節點 設定 → 整合 → 新增 **Local IP** → `sensor.local_ip`。

## 7.6 回切手冊（主節點修好後，手動，約 10 分鐘）

| 步驟 | 在哪台 | 動作 |
|---|---|---|
| 1 | 副節點 | 設定 → 系統 → 備份 → 立即備份（全備，含這段期間的狀態）；記下檔名 |
| 2 | 副節點 | 附加元件 → Zigbee2MQTT → **停止**，取消「開機時啟動」（放開 SLZB-06） |
| 3 | 主節點 | 開機，確認 `http://192.168.0.18:8123` 可開 |
| 4 | 主節點 | 設定 → 系統 → 備份 → 從 standby 位置選步驟 1 的檔 → 還原（勾 config + Z2M + Mosquitto）→ 自動重啟後 `s00_node_started_on_primary` 會啟動 Z2M |
| 5 | 副節點 | 把 `/config/packages/` 清到只剩 `standby_node.yaml`，`input_boolean.promoted` 關閉，重新啟動 HA |
| 6 | 兩人手機 | Companion App 切回「主節點」伺服器 |
| 7 | 主節點 | 開發者工具 → 狀態：`binary_sensor.is_primary_node` = on；Z2M 記錄 `Zigbee2MQTT started!` |

不做自動回切的原因：主節點若「時好時壞」，自動回切會讓兩台反覆爭 SLZB-06 與雲端登入；人工確認穩定後再切最安全。

## 7.7 遠端存取

### A. DuckDNS + Let's Encrypt + NGINX（主節點，給 Companion App 外部網址）

主節點附加元件：**Duck DNS**（`domains: [AllenandAnn.duckdns.org]`、token、`lets_encrypt.accept_terms: true`）→ **NGINX Home Assistant SSL proxy**（`domain` 同上）。路由器 443 → `192.168.0.18:443`。HA 設定 → 網路：外部網址 `https://AllenandAnn.duckdns.org`。兩個帳號都開 TOTP；`http:` 加 `ip_ban_enabled: true`、`login_attempts_threshold: 5`。

接手時 443 仍指向死掉的主節點（消費級路由器無法自動改），所以外部入口靠 B。

### B. Tailscale（兩台都裝，不需埠轉發，接手後手機不用改設定）

1. 兩台 HAOS 都裝 **Tailscale** 附加元件 → 記錄中的登入網址用同一個 Tailscale 帳號授權 → 各拿到 `100.x.y.z` 位址與 MagicDNS 名稱（`homeassistant-main`、`homeassistant-standby`，在 Tailscale 後台改名）。
2. 兩支手機裝 Tailscale App 並登入。
3. Companion App → 伺服器：主節點外部網址填 `http://homeassistant-main:8123`（或 DuckDNS https），備援伺服器外部網址填 `http://homeassistant-standby:8123`。
4. Tailscale 後台 → DNS → 關閉其他裝置的 MagicDNS 覆寫不需要；ACL 預設同帳號互通即可。

接手後手機在 App 左上角切到「備援」即可，家內外都通。

### C. WireGuard（選配，管理用）

主節點 WireGuard 附加元件 + 路由器 51820/udp → `.18`；有 Tailscale 後可省略。

## 7.8 Hermes 的節點容錯

`hermes/config/hermes.yaml`：

```yaml
ha:
  urls:
    - http://192.168.0.18:8123   # 主節點
    - http://192.168.0.28:8123   # 副節點（接手後 token 相同，因 .storage 一起還原）
  token_env: HERMES_HA_TOKEN
  timeout_s: 1.1
  health_interval_s: 60
```

`ha.py` 每 60 秒 ping `/api/` 決定目前使用哪個節點；呼叫途中連線失敗也會立即切換並重試一次（tx log 會記 `ha_switch → .28`）。Mac mini 整台掛掉時 Hermes 也一起掛，這段容錯只對「HAOS VM 掛、Mac mini 還活著」有用。

## 7.9 驗證清單

| # | 檢查 | 預期 |
|---|---|---|
| 1 | 主節點 設定 → 備份 | 上次自動備份 03:0x，位置含 standby |
| 2 | 副節點 `smb://192.168.0.28/backup` | 有 `hourly_HH.tar` ×24 與每日全備 |
| 3 | 副節點 設定 → 自動化 | 只有 3 個 `備援：` 自動化；沒有任何情境 |
| 4 | 副節點 Z2M 附加元件 | 已安裝、未啟動、不隨開機啟動 |
| 5 | SLZB-06 網頁 | 顯示 1 個 client 連線（來自 .18） |
| 6 | **接手演練**：關閉主節點 HAOS VM（`utmctl stop HAOS`） | 5 分鐘後兩人收到推播；再 2 分鐘後副節點開始還原；約 4 分鐘後收到「備援機已接手」；Tap 鍵與 App 能控燈 |
| 7 | 演練中 Hermes | `tail hermes.tx.log` 有 `ha_switch`；「客廳幾度」仍有回答 |
| 8 | **回切演練**（§7.6） | ≤ 10 分鐘；SLZB-06 client 回到 .18 |
| 9 | 關閉 `auto_promote` 再關 VM | 只推播附「接手／取消」按鈕，按「接手」才還原 |
| 10 | 手機 4G + Tailscale 開備援伺服器 | 可開 |
| 11 | 手機 4G 用 Fing 掃固定 IP | 只有 443（與選配 51820） |
| 12 | `secrets.yaml` 的 `backup_password` | 兩台相同；紙本貼在 HA Black 機身 |

每季做一次 6 + 8。
