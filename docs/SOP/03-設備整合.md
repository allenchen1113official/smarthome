# 03 · 設備整合

> 目標：所有設備出現在 HA、依 §0.5 命名、歸入正確區域、輔助實體建好、通知群組與地理圍欄可用。
> 完成判準：§3.12 檢查全部通過。做完這章，儀表板已能手動控制全屋。

每個整合都走同一個節奏：**加整合 → 改 entity_id → 指派區域 → 在儀表板按一次確認會動**。

## 3.1 HACS（社群整合商店）

Panasonic、Hue Sync Box、SmartIR 都在 HACS。

1. Terminal & SSH 附加元件：`wget -O - https://get.hacs.xyz | bash -`
2. 重新啟動 HA → 設定 → 整合 → 新增 → `HACS` → 依指示用 GitHub 帳號授權。
3. 側欄出現 HACS。

## 3.2 Philips Hue（Bridge + 18 燈 + Tap + Dimmer ×2 + Motion ×2）

1. Hue App 先把全部燈具、Tap、Dimmer、Motion 都加到 Bridge，並在 Hue App 建好**房間**（名稱同 HA 區域）與以下**場景**（Hermes `light.activate_scene` 的 enum 只接受這些名稱）：
   `Welcome`、`Sunrise`、`Dinner`、`Movie`、`Nightlight`、`Focus`
   建議值：Welcome 4000K 80%｜Sunrise 2200K 10%→30 分鐘內漸亮｜Dinner 2700K 65%｜Movie 客廳崁燈 10% + Play 燈條 Sync｜Nightlight 1% 暖白｜Focus 5000K 100%。
2. HA 設定 → 整合 → 新增 → **Philips Hue** → 自動找到 `192.168.0.20` → 依指示**按 Bridge 實體按鈕**。
3. 整合會匯入燈具、房間（成為 HA 燈群）、場景、感測器。逐一改名：
   - 燈：`light.living_1`…`light.living_10` 等。
   - 房間燈群：`light.living_all`、`light.master_all`、`light.second_all`。
   - Motion：`binary_sensor.hallway_motion`、`binary_sensor.living_motion`；附帶的照度 `sensor.hallway_illuminance`、`sensor.living_illuminance`、溫度 `sensor.hallway_temperature`。
   - 場景：HA 會自動產生 `scene.<房間>_<場景>`；本手冊的 packages 與 12 章儀表板**固定用**下列 ID，匯入後若不同請改成這些：`scene.living_welcome`、`scene.living_dinner`、`scene.living_movie`、`scene.living_focus`、`scene.master_sunrise`、`scene.master_nightlight`。（`scene.before_movie`、`scene.before_dry` 是情境執行時用 `scene.create` 暫存的快照，不必建立。）
4. 建全屋燈群：設定 → 裝置與服務 → 輔助實體 → 新增 → **群組 → 燈光群組** → 名稱 `All Lights` → 選所有崁燈 → entity_id 改 `light.all_lights`。
5. **按鍵事件**：Hue Tap / Dimmer 不會變成實體，而是發 `hue_event` 事件。找出每顆按鍵的 ID：開發者工具 → 事件 → 監聽 `hue_event` → 按一下按鈕 → 記下 `id`（例如 `hue_tap_button_1`）與 `type`（`initial_press` / `repeat` / `short_release` / `long_release`）。把四顆 Tap 鍵與兩顆 Dimmer 的 id 填進 06 章對應情境。
6. 在 Hue App → 設定 → 配件 → Motion：把兩顆感測器的「日間/夜間」自動化**全部刪除**（否則 Hue 自己也會開燈，和 HA 打架）。

## 3.3 Hue Play HDMI Sync Box（HACS）

1. HACS → 整合 → 搜尋 `Philips Hue Play HDMI Sync Box` → 下載 → 重啟 HA。
2. 設定 → 整合 → 新增 → `Philips Hue Play HDMI Sync Box` → 自動找到 `.21` → **按 Sync Box 實體按鈕 3 秒** 完成配對。
3. 改名：`switch.hue_sync_box_power`、`select.hue_sync_box_mode`（video/music/game）、`select.hue_sync_box_intensity`。

## 3.4 Panasonic 空調（⚠️ 雲端 + 本地 IR 雙路徑）

### A. Panasonic Comfort Cloud（HACS `panasonic_cc`，雲端）

1. 手機 Panasonic Comfort Cloud App 先把三台室內機（WiFi 模組）加入，連 `AllenAnn-IoT`。
2. HACS → 整合 → 搜尋 `Panasonic Comfort Cloud` → 下載 → 重啟。
3. 設定 → 整合 → 新增 → `Panasonic Comfort Cloud` → 帳密。
4. 改名：`climate.living`、`climate.master`、`climate.second`；區域對應。
5. 它是雲端 API：Comfort Cloud 掛掉時 HA 顯示 `unavailable`。所以加 B。

### B. Broadlink RM4 mini + SmartIR（本地 IR 備援）

1. Broadlink App 把 3 顆 RM4 mini 加入 `AllenAnn-IoT`，**鎖定裝置關閉**（App → 裝置設定 → 「Lock device」關），否則 HA 連不上。
2. HA 設定 → 整合 → 新增 → **Broadlink** → 自動發現 `.55/.56/.57`。
3. HACS → 整合 → `SmartIR` → 下載 → 重啟。SmartIR 內建 Panasonic 碼表（device_code 約 `1000`–`1099` 系列，先用 `1000` 測，不合再換；或自行用 Broadlink 學習）。
4. `configuration.yaml`（已含在 snippet）：

```yaml
climate:
  - platform: smartir
    name: Living AC IR
    unique_id: living_ac_ir
    device_code: 1000
    controller_data: remote.rm4_living
    temperature_sensor: sensor.living_temperature
    humidity_sensor: sensor.living_humidity
  - platform: smartir
    name: Master AC IR
    unique_id: master_ac_ir
    device_code: 1000
    controller_data: remote.rm4_master
    temperature_sensor: sensor.master_temperature
    humidity_sensor: sensor.master_humidity
  - platform: smartir
    name: Second AC IR
    unique_id: second_ac_ir
    device_code: 1000
    controller_data: remote.rm4_second
```

5. 06 章所有空調動作都呼叫 `script.ac_set`（在 `packages/s00_common.yaml`）：它先用 `climate.living`（雲端），若 `unavailable` 就改用 `climate.living_ac_ir`。這就是憲章 II 的「優雅降級」。

## 3.5 Zigbee2MQTT：Aqara 窗簾 ×2、門窗、溫濕度、人體、插座、繼電器

1. Z2M 前端 → **Permit join (All)** → 240 秒內把設備進入配對模式：
   - Aqara 窗簾 c3：長按機身按鈕 5 秒直到藍燈閃。
   - Aqara 門窗 / 溫濕度 / Motion P1：長按配對鍵 5 秒。
   - 插座：長按電源鍵 5 秒。
2. 每個設備在 Z2M 前端 → **Rename**（勾 update HA entity id）：

| Z2M friendly name | HA entity |
|---|---|
| `living_curtain` | `cover.living_curtain` |
| `bedroom_curtain` | `cover.bedroom_curtain` |
| `front_door` | `binary_sensor.front_door` |
| `master_window` | `binary_sensor.master_window` |
| `master_th` | `sensor.master_temperature` / `sensor.master_humidity` |
| `living_th` | `sensor.living_temperature` / `sensor.living_humidity` |
| `bath_th` | `sensor.bath_humidity` |
| `bath_motion` | `binary_sensor.bath_motion`（P1 附照度 `sensor.bath_illuminance`） |
| `second_desk_plug` | `switch.second_desk_plug` / `sensor.second_desk_plug_power` |
| `bath_fan_relay` | `switch.bath_fan` |

3. 窗簾校正：Z2M 設備頁 → Exposes → 先 `open` 到底、`close` 到底各一次讓馬達記住行程；確認 `position: 100` 是全開。若方向相反勾 `reverse_direction`。
4. 感測器放置：主臥溫濕度放床頭櫃（離冷氣出風口 > 2 m）；浴室溫濕度放門框上方；門窗感測器磁鐵間距 < 1 cm。
5. Zigbee 網狀：插座類是路由器，先配對插座再配對電池設備，訊號會更好。

## 3.6 Roborock Qrevo Edge C

1. Roborock App 把機器加入 `AllenAnn-IoT`，建好房間地圖（命名：客餐廳、主臥、次臥、玄關、浴室）。
2. HA 設定 → 整合 → 新增 → **Roborock** → 帳密（登入雲端取得本地金鑰，之後指令走區域網路）。
3. 改名：`vacuum.qrevo`、`camera.qrevo_map`、`sensor.qrevo_water_tank`（若型號提供）、`sensor.qrevo_filter_left` 等。
4. 開發者工具 → 狀態 → `vacuum.qrevo` 屬性會有 `room` 對照表（房間 ID），記下來給情境 19。

## 3.7 HomePod ×2（AirPlay 輸出）

1. HA 設定 → 整合 → 新增 → **Apple TV** → 會列出 HomePod 與 HomePod mini → 選 → 以 AirPlay 配對（輸入螢幕上 PIN；HomePod 無螢幕時會自動完成）。
2. 改名：`media_player.living_homepod`、`media_player.master_homepod_mini`。
3. 測試：開發者工具 → 動作 → `tts.speak`（04 章裝好 Piper 前先用內建 `google_translate` 作測試，之後移除）。

HomePod 進聲（麥克風）路徑見 04 章；這裡只負責「HA 能對 HomePod 講話」。

## 3.8 HA Companion App（Allen / Ann 手機）

1. 兩支 iPhone 裝 Home Assistant App → 伺服器 `http://192.168.0.11:8123`（07 章後改為 `https://AllenandAnn.duckdns.org`）。
2. 各自用自己的帳號登入；App 設定 → Companion App → **位置** 開「背景更新」、**感測器** 開「地理位置」。
3. HA 設定 → 人員：把 `person.allen` 綁 `device_tracker.allen_iphone`、`person.ann` 綁 `device_tracker.ann_iphone`。
4. 通知群組與「2 km 預熱」距離（`configuration.yaml` snippet 已含）：

```yaml
notify:
  - name: both
    platform: group
    services:
      - service: mobile_app_allen_iphone
      - service: mobile_app_ann_iphone

proximity:
  home_allen:
    zone: home
    devices: [device_tracker.allen_iphone]
    tolerance: 50
    unit_of_measurement: m
```

5. iPhone 設定 → Home Assistant → 通知 → 允許「時效性通知」（深夜停損告警與主機失聯要用）。
6. 測試：開發者工具 → 動作 → `notify.both` 送一則訊息，兩支手機都要收到。

## 3.9 天氣與空氣品質

- 內建 **Met.no**（設定 → 整合 → 新增 → Meteorologisk institutt）：無需金鑰 → `weather.home`。
- 選配：HACS `中央氣象署 (CWA)`（需 CWA 開放資料 API key）給更準的台灣預報；`weather.cwa_home`。
- 空品：HACS 搜尋 `Taiwan AQI` / `環境部 AQI`（需環境部 API key）→ `sensor.aqi_home`。沒有就在情境 02 的播報文字中省略空品段。

## 3.10 網路與節點實體（情境 26 / 27、07 章熱備）

設定 → 整合 → 新增 **Local IP** → `sensor.local_ip`；`packages/s00_node.yaml` 用它判斷「我是主節點（.11）還是副節點（.12）」。

```yaml
binary_sensor:
  - platform: ping
    name: wan_ping
    host: 1.1.1.1

```

（`binary_sensor.macmini_ping` 與接手邏輯設在**副節點** HA Black 的 `standby/standby_node.yaml`，07 章。）

## 3.11 輔助實體一次建完
