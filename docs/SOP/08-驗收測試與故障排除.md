## 8.2 故障排除

### Mac mini / HAOS VM

| 症狀 | 檢查 | 處置 |
|---|---|---|
| 重開後 HA 沒回來 | `utmctl list` | `utmctl start HAOS`；確認登入項目有 UTM、自動登入已開 |
| VM 拿不到 .11 | VM `ha network info` | UTM 網路要 **Bridged** 且介面選 `en0`；MAC 要和 DHCP 保留一致 |
| Zigbee2MQTT `Adapter disconnected` / 連不上 SLZB-06 | SLZB-06 網頁是否已被另一個 client 佔住 | 副節點 Z2M 未停止會搶走連線：副節點停止 Z2M；SLZB-06 重開；仍不穩 → 檢查 PoE 供電與網路線 |
| HA 很慢、CPU 滿 | 活動監視器 `qemu` | VM 給 2 核即可；若 Ollama 同時推理，屬正常瞬間負載 |
| `/Volumes/config` 消失 | Finder | 重新連接伺服器；登入項目加入磁碟 |

### 網路

| 症狀 | 處置 |
|---|---|
| 手機在家連不到 `homeassistant.local` | 用 IP `192.168.0.11:8123`；路由器開 IGMP Snooping；Companion 內部網址綁 SSID |
| HomePod 在 HA `unavailable` | HomePod 必須在主 SSID（不是 IoT）；Apple TV 整合重新配對 |
| 空調 `unavailable` | Comfort Cloud 伺服器問題；`script.ac_set` 已自動走 IR；App 看記錄簿「走 IR 備援路徑」 |
| 外部 https 打不開 | DuckDNS 附加元件記錄；路由器 443 轉發到 `.11`；`curl -vI https://AllenandAnn.duckdns.org` |

### OpenClaw / Hermes

| 症狀 | 檢查 | 處置 |
|---|---|---|
| Assist 回「等我一下」 | `tail ~/openclaw/hermes/logs/hermes.err` | LLM 車道塞住；`ollama ps` 確認模型常駐；重啟 `launchctl kickstart -k gui/$(id -u)/com.allenann.hermes` |
| 回「這個我還不會」 | tx log `PARSED` 行 | LLM 產生了不存在的工具名；加 alias 或在 `llm.py` SYSTEM 補範例 |
| STT 把「主臥」聽成「主握」 | whisper.err | 確認已是 `mlx-whisper large-v3-turbo`（04 §4.4）；`--initial-prompt` 加常用詞 |
| 回覆很慢且 tx log 有 `<think>` | hermes.err | Qwen3 thinking 沒關：`hermes.yaml` `ollama.think: false`；Ollama 升到支援 `think` 參數的版本（≥ 0.9） |
| whisper.err `No module named mlx` | — | 不是 Apple Silicon 或 Python 3.14：改回 faster-whisper（04 §4.4 末） |
| Piper 讀數字怪 | — | `textnorm.for_tts` 已轉中文數字；HA 自己的 TTS 文字請寫中文數字 |
| 深夜沒收到確認推播 | iPhone 通知設定 | 允許「時效性通知」；`notify.push` tag `hermes_confirm` |
| `/v1/jobs/screen` 回 results 空 | hermes.err `quote fail` | TWSE 端點被限流或假日；15 分鐘後再試；`market.yaml` `timeout_s` 加大 |
| world_entities = 0 | hermes.err `WS 斷線` | token 失效 → 重新建立長效 token；`ws_enabled: false` 可暫退 REST |
| 記憶體壓力黃/紅 | 活動監視器 | Whisper 改 `large-v3-turbo-q4`（省 1.1 GB）；Ollama 改 `qwen3:4b`（2.6 GB）；或 HAOS VM 降 1.5 GB |

### 青鳥 Docker 路線 / 負載均衡

| 症狀 | 檢查 | 處置 |
|---|---|---|
| 後台「套用」後容器沒變 | 後台總覽「重啟」結果 | 埠／profile 變更要在主機 `docker compose up -d`；docker.sock 是否掛載 |
| 套用後 HA 設定無效 | HA 設定 → 系統 → 記錄 | 開發者工具 → YAML → 檢查設定；`packages/s00_magpie.yaml` 由後台產生，勿手改 |
| 副節點沒收到備份 | 主節點後台事件「推送失敗」 | 兩邊 `shared_secret` 相同；副節點 9000 可達；時間同步 |
| 副節點誤接手 | 副節點事件 | 主節點後台 9000 被防火牆擋 → 放行；或關 `auto_promote` 改手動 |
| VIP 不在任何 LB | 兩台 `ip addr`、`journalctl -u keepalived` | 同網段、`virtual_router_id` 相同、`auth_pass` 相同；VM 橋接而非 NAT |
| HAProxy 後端全 DOWN | `:8404/stats` | 健康檢查路徑／期望碼；節點防火牆；`ip_nonlocal_bind` |
| Telegram 機器人沒回 | `docker compose logs bot` | token 正確；成員 ID 已在白名單；同一 token 只能有一個 polling（副節點 bot 必須停止） |
| LINE webhook 驗證失敗 | LINE Console Verify | 443 → bot:8900 的反向代理路徑 `/line/webhook`；Channel secret 正確 |
| Grok 沒生效 | `docker compose logs hermes` | `GROK_API_KEY`；`llm.provider: grok`；看是否 `fallback → ollama` |
| 冷氣設 24 卻變 27 / 燈只到 40% | 回覆句尾「節能：…」 | 這是守門正常行為；說「這次不要省」或後台切 normal/comfort；長期不要就關 `input_boolean.energy_guard` |
| 用電報告「還沒有用電資料」 | `sensor.home_energy_total` | Shelly EM 未加入或實體名不同（03 §3.8b）；`utility_meter` 要等第一個整點 |
| 無人時空調沒關 | `binary_sensor.home_nobody` | person 實體沒更新（Companion 定位）；`energy_mode = comfort` 時 e01 不動作 |

## 8.3 備案：Zigbee2MQTT 改在 macOS 主機跑

```bash
brew install node
sudo npm i -g zigbee2mqtt
mkdir -p ~/openclaw/z2m && cd ~/openclaw/z2m
cat > configuration.yaml <<'EOF'
mqtt: { base_topic: zigbee2mqtt, server: mqtt://192.168.0.11:1883, user: mqtt, password: '<mqtt 密碼>' }
serial: { port: /dev/tty.usbserial-XXXX, adapter: ember }    # ls /dev/tty.usb*
advanced: { channel: 15, network_key: GENERATE, pan_id: GENERATE, ext_pan_id: GENERATE }
frontend: { port: 8099 }
homeassistant: { enabled: true }
permit_join: false
EOF
Z2M_DATA=~/openclaw/z2m zigbee2mqtt    # 正常後寫成 launchd plist（仿 04 章）
```

停用 HAOS 內的 Z2M 附加元件、取消 UTM USB 直通。Zigbee 網路金鑰不同，設備需重新配對一次。
